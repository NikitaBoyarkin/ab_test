# EDA Findings — ab_test (`data/experiment_sample.csv`)

**Дата:** 2026-10-13
**Полный отчёт:** `reports/eda/eda-ab-test-2026-10-13.md`

## Датасет вкратце

`data/experiment_sample.csv` содержит 600 строк, одна строка = один **пользователь** A/B-эксперимента
(8 колонок: `day, segment, treat, conv, pre_conv, pre_sessions, impressions, clicks`). Период —
относительные дни 0–2 (3 дня, по 200 юзеров/день). Качество данных в целом — **хорошее**: 0 пропусков,
все диапазоны валидны, `clicks ≤ impressions` в 100% строк, SRM чист (χ² p = 0.514).

## Топ проблем качества

### Проблема 1: README-headline относится к DGP 42k, а не к фикстуру (привязка закрыта)
- **Что:** README (README.md:3, 28–31, 51–61) заявляет CTR **+0.51pp** (p<0.0001) и CUPED **17.7%**;
  на этом файле CTR даёт **+0.37pp, p = 0.207** (незначимо), CUPED — **14.9%**.
- **Влияние:** читатель может решить, что числа относятся к `experiment_sample.csv`. Числа
  воспроизводятся, но на другом датасете (синтетический DGP пайплайна, 42 000 юзеров, seed=7).
- **Действие:** блок «Source of these numbers» в README.md:56–61 привязывает таблицу к DGP 42k и
  приводит числа фикстура рядом — **сделано 2026-10-18**. Остаточное: значения таблицы держатся на
  прогоне пайплайна, теста на числа нет — либо пин тестом, либо перегенерировать фикстур из
  `generate_data()`.
- **Владелец:** аналитик / автор репозитория.

### Проблема 2: Per-segment эффект разворачивает знак (риск ложного таргетинга)
- **Что:** pooled ATE +2.75pp, но внутри сегментов `desktop +7.3pp`, `mobile +3.2pp`, `tablet −6.3pp`;
  после BH все p_adj ≥ 0.347 (ни один не значим). Tablet n = 57/69.
- **Влияние:** если таргетировать по этому файлу, можно увести бюджет в сегмент, где эффект может
  быть отрицательным (или это чистый шум).
- **Действие:** не таргетировать; pre-register гипотезу про tablet и прогнать тест с расчётом мощности.
- **Владелец:** продуктовый аналитик.

### Проблема 3: 5.0% IQR-выбросов в `impressions` (на пороге WARN)
- **Что:** 5.0% юзеров вне `Q1−1.5·IQR … Q3+1.5·IQR`; распределение лог-нормальное (skew 1.68).
- **Влияние:** среднее `impressions` (39.7) завышено против медианы (34) на +17% — на среднем строить
  срезы нельзя.
- **Действие:** принять (это реальные heavy-users, не ошибка); докладывать медиану для счётных колонок.
- **Владелец:** аналитик.

### Проблема 4: 3 полных дубликата строк (0.5%) без ключа для проверки
- **Что:** 3 строки полностью идентичны; в схеме нет `user_id`, проверить дубликаты по ключу нельзя.
- **Влияние:** < 1% (порог FAIL), но подтвердить «один юзер один раз» невозможно — методологическое
  ограничение, не ошибка данных.
- **Действие:** принять риск; для реального эксперимента добавить `user_id` в схему.
- **Владелец:** дата-инженер.

### Проблема 5: «novelty-форма» — описание, не вывод
- **Что:** дневные конверсии рисуют сходящиеся кривые (treat 0.210 → 0.160, control 0.140 → 0.170),
  но `treat×day` = −0.040/день, 95% CI [−0.114, +0.034], p = 0.290; MDE при 80% мощности — 10.6pp/день.
- **Влияние:** формулировка «эффект затухает» выводится из шума: файл не отличает затухание от
  стабильности.
- **Действие:** заявлять можно только «|interaction| ≥ 10.6pp/день исключён»; для novelty — ≥2 недели
  с always-valid мониторингом.
- **Владелец:** аналитик.

## Что в порядке

- 0 пропусков во всех 8 колонках; константных колонок нет.
- `conv`, `pre_conv`, `treat` — строго {0,1}; `segment` — только {mobile, desktop, tablet}.
- `clicks ≤ impressions` во всех 600 строках (CTR определён на каждом юзере).
- SRM: 292 vs 308, χ² p = 0.5136 — бакетинг-баг не обнаружен (α = 0.001).
- Покрытие по дням непрерывное: по 200 юзеров в день 0/1/2, разрывов нет.
- Состав сегментов по рукавам совпадает (Simpson-guard пройден): desktop 39.4/38.3%,
  mobile 41.1/39.3%, tablet 19.5/22.4%.
- Суммы по сегментам сходятся с агрегатом: 48 + 35 + 20 = 103 = число `conv = 1`.
